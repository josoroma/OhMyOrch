## 1. Objective

Give the harness a way to produce self-contained, single-page HTML documents. Each page
uses the shadcn Luma theme in light and dark and opens with a table of contents. It can
explain content through tables, lists, SVG diagrams with overlays, SVG
entity-relationship diagrams, and SVG infrastructure diagrams. The pages serve two
purposes: demonstrating codebase status, and explaining the codebase and spec-driven
development to developers.

## 2. What existed before

The harness documented itself only in Markdown: `README.md`, `scripts/README.md`, and
these per-epic records. There was no visual artifact, no theme, and no check that a
generated document was well formed, cited its figures, or loaded nothing from the
network.

## 4. Key design decisions

1. **A skill, not an agent.** The work is a procedure: gather evidence, fill the
   template, validate. It needs no independent authority.
2. **One file, nothing from the network.** Styles, scripts, and diagrams are inline.
   The page opens from disk and still renders years later.
3. **The Luma tokens are the contract.** All 32 light and 31 dark tokens are embedded
   verbatim in the template and in the validator. Components colour only through
   `var(--token)`, so every diagram switches with the theme.
4. **The browser enforces self-containment.** Static HTML and CSS scanning cannot be
   complete (see §6). Every page therefore opens `<head>` with
   `default-src 'none'; script-src 'unsafe-inline'; style-src 'unsafe-inline'; img-src data:`.
   The `csp` rule checks that the policy is the first element in `<head>`, reading the
   bytes as an HTML parser does.
5. **Never invent a figure.** A page that reports status keeps `section#sources`,
   which cites the file or command behind every number.
6. **Overlays explain in place.** Each note is anchored beside its numbered pin. A
   layout pass keeps notes from overlapping, and falls back to a list under the
   diagram when they cannot fit. Any outside click, or Escape, closes the notes.
   These were human PM requests during delivery.

## 6. Review and reopen history

Six review rounds. Every one of the first five found the validator accepting a page
that the spec forbids.

| Round | Verdict | What it found | Remediation |
|---|---|---|---|
| r1 | fail | **F-1** a single-quoted or multi-token `rel` stylesheet passed; **F-2** an unpredicted deletion of `README-OPENSPEC-COMMANDS.md` | `rel` matched as a token list; the deletion confirmed by the PM and its references removed |
| r2 | fail | **F-3** a padded `=`, `/` separators, and `>` inside quoted values evaded the tag patterns | an attribute tokenizer that follows HTML rules |
| r3 | fail | **F-4** 20 more spellings loaded external resources in Chrome: form feed, character references, duplicate attributes, comment quirks, SVG script, CSS escapes. **F-5** inline scripts loading code at run time | a required Content-Security-Policy and the `csp` rule |
| r4 | fail | **F-6** the policy tag passed with a vertical tab, or with `İ` folded under a UTF-8 locale; Chrome ignored the policy | HTML whitespace only, ASCII case folding under `LC_ALL=C`, printable-ASCII prefix |
| r5 | fail | **F-7** a NUL byte in the policy tag was invisible to grep and awk | NUL mapped to `\001` before any tool reads the page |
| r6 | **pass** | no blocking findings; 7/7 scenarios | — |

Acceptance, per `test-report.md`: **7/7 scenarios PASS**. The Tester drove the theme
toggle in headless Chrome, confirming the class toggles, the choice persists, and the
page follows the system setting. The Tester also built its own probe pages for every
rule.

## 7. Known limits

- **Rule output outside `csp` can depend on the caller's locale.** `csp` itself runs in
  the C locale (review r6 observation).
- **Only external scripts, stylesheets, and fonts are in scope.** A
  `<meta http-equiv="refresh">` to a remote URL still passes, because the spec covers
  those three resource kinds, not navigation. Whether to cover navigation is a PM
  decision.
- **`csp` is stricter than the browser in one case.** A NUL right after
  `<meta charset>` fails, although Chrome applies the policy.
- **An `@import` placed just before the `:root` block misleads.** The page correctly
  fails `self-contained`, but it also reports all 32 light tokens as changed (test
  report observation).
- **No NUL-tolerant awk was run.** Its behavior was simulated, not run on a Linux
  host.
