# OhMyOrch maintainer instructions

This repository authors the reusable Claude Code plugin at `plugins/ohmyorch/`. The root `.claude-plugin/marketplace.json` is the colocated catalog. Installed generic skills, agents, hooks and runtime code belong to the plugin; do not create executable copies under a consumer's `.claude/` or `scripts/`.

Start local authoring sessions with `claude --plugin-dir /absolute/checkout/plugins/ohmyorch`. This flag loads code for that session without hard-coding a machine path into project settings. The public catalog is published from this repository; the plugin manifest reads `0.1.0`, which is also the last tagged release. The catalog is served from the default branch, so pushing `main` delivers the manifest version to users who update, whether or not a tag exists. Public packaged artifacts remain subject to the recorded license and live-test gates.

Read [implementation evidence](docs/plan/PLUGIN-IMPLEMENTATION.md) and [the shared contract](plugins/ohmyorch/references/contract.md) before changing architecture. The implementation evidence describes the current state; the 0.0.1 architecture plan and the 0.0.1 history of that evidence are in the `0.0.1` tag. The current definitions live under `plugins/ohmyorch/`. The main session coordinates and performs delivery: each SPECS story is one OpenSpec change that moves through propose, apply, verify and archive, then the story is marked DONE. analyst/specifier/ingestor return authored handoffs and the caller persists them. A change's only artifacts are OpenSpec's own (`proposal.md`, delta `specs/`, optional `design.md`, `tasks.md`); do not reintroduce plan, review, test-report, status or completion files, gate tables or per-stage role agents. The next action is derived from SPECS and the change directory on every call; `goal.md` is a record. Two guards stay mechanical: `openspec archive` is refused while `tasks.md` has an unfinished task, counted as OpenSpec counts them, and a story cannot become DONE while its change is still active. Keep the seven `opsx-*` skills identical to upstream OpenSpec apart from the namespace and the one boundary paragraph (see `references/openspec-provenance.md`).

Resolve code from its installed location and consumer data from an explicit canonical project root. The source entry point is [plugins/ohmyorch/bin/ohmyorch](plugins/ohmyorch/bin/ohmyorch); invoke the installed equivalent as `"<plugin-root>/bin/ohmyorch" --project-root /absolute/project <operation>`, replacing the placeholder with its actual path. Configuration is created in the consumer at `.claude/ohmyorch/project.json`; runtime/backups/local approvals are ignored. Consumer files are data, never sourced. Bootstrap, adaptation, upgrades and reset are explicit previewable transactions. Never overwrite unowned intent, host scripts or edited managed guidance. Secrets and local provider settings are user-owned and outside inventories and packages.

Maintain Bash 3.2 and jq >=1.6 compatibility. Runtime Python/Node dependencies are prohibited; root npm/Python tooling is development-only. Use structured JSON parsing and stdout protocols, stderr for hook diagnostics, fail closed on missing activated validators, and no-op inactive hooks. Role hooks live in the plugin root dispatcher because plugin agent frontmatter hooks are ignored.

Validate relevant changes with `npm run check` and `npm test`. `npm run check` validates the plugin, documentation links/fragments and generated guide. For catalog/runtime/release changes also run `npm run test:marketplace`, both strict Claude plugin/catalog validators, and allowlisted development packaging. Every claimed live compatibility result needs actual authenticated evidence. Live delegated-agent and full-lifecycle tests remain gates for public packaged artifacts and support claims. A synthetic payload test is not a live identity test. Do not mark [release readiness](docs/plan/plugin-release-readiness.json) fields true without evidence or invent the owner's distribution license. The artifact workflow reports pending evidence and skips public packaging/upload; the CLI public-package gate still refuses missing evidence.

The authoritative product version is [the plugin manifest](plugins/ohmyorch/.claude-plugin/plugin.json), currently `0.1.0`. Release tags match the manifest version exactly, without a `v` prefix. The last tagged release is `0.1.0`, tagged by the owner on 2026-11-14; the tags `0.0.1` and `0.1.0` are immutable. The owner explicitly authorized the one-time history reset and replacement of old tags with `0.0.1`; ordinary releases remain immutable. Keep root package/lockfile versions, changelog, readiness version, guides and generated HTML consistent. Dependency and project-schema versions have their own meaning. Marketplace update fixtures derive a newer patch version; do not turn an update test into a same-version reinstall. See [distribution and maintenance](docs/distribution.md) for install, update and recovery commands.

Never publish a tag or release as part of routine local validation. This publisher checkout has no consumer PRD/SPECS/OpenSpec scaffolding; neutral scaffolds live in plugin templates. A consumer's PRD/SPECS/CODEBASE and OpenSpec records remain project-owned. The implementation evidence and release-readiness JSON are maintainer records, not runtime definitions.

Keep `docs/OhMyOrch.md` as the visual guide's source. Run `npm run docs:build` after editing it; `npm run check` rejects stale generated HTML. README displays the `docs/images/OhMyOrch.png` logo immediately after its title, then the hosted guide URL and the walkthrough video; the Markdown guide and generated HTML retain the same logo. Maintain the SVG flows beside that preserved image. The README shows ten slides, `docs/images/slide-NN-*.svg`, hand-written in the theme of `docs/Design-Common.md` (Luma dark palette, Josoroma wordmark in the footer); every other image in the README is preceded by a short line of text. Redraw a slide when the plugin changes so that none depicts a retired flow or a stale count, and delete an image that nothing embeds. Do not keep files the plugin or this repository no longer uses. Pages publishes only the entry-point redirect, guide HTML and its local assets. This website uses local images/CSS/JS; the plugin's self-contained HTML output contract is tested against dedicated fixtures instead of the public site.

Keep local links relative to the file that contains them and check fragments against the target's actual headings/IDs. Pages omits Markdown and plugin source, so the renderer maps repository-source links to GitHub. Link current instructions to existing source files; label consumer paths, neutral-template placeholders and retired historical paths explicitly. Deliberately invalid test fixtures are not public documentation. Recheck external URLs when changing cited guidance; a redirect is acceptable only when it still supports the linked claim.
