OMOhMyOrch

Spec-driven Claude harness

OhMyOrch makes agentic delivery auditable.

It turns product intent, codebase context, and a READY backlog into small planned, implemented, reviewed, tested, and archived OpenSpec changes.

Problem

Agent speed needs rails.

FrictionOhMyOrch response
Product intent gets mixed with code guesses.PRD.md and SPECS.md come from product sources; CODEBASE.md is evidence only.
One session plans, implements, reviews, and approves itself.Separate agents own planning, implementation, review, and test artifacts.
Work disappears into chat history.Every handoff is a durable file under openspec/changes/ or a root product document.
Done is ambiguous.Status: DONE requires review, test, completion evidence, archive, and synced specs.

Execution

One story, one pass through the gates.

/ohmyorch-deliver <EPIC-N | US-N.M | US-N.M#k | "task text"> runs the ohmyorch-deliver skill. The main session is the orchestrator, acting as the Product Manager. It delivers each story as its own OpenSpec change, in SPECS.md order.

SelectProduct Manager: openspec new change
Proposeohmyorch-planner: explore + propose
Planohmyorch-planner: /ohmyorch-plan-feature
Implementohmyorch-implementer: /ohmyorch:opsx:apply
Reviewohmyorch-reviewer: review.md + verify
Testohmyorch-tester: test-report.md
Archivecompletion gate, archive, story DONE
Step 0  scripts/delivery.sh resolve <target>; scripts/delivery.sh start <target>   -> goal.md ACTIVE
Step 1  scripts/delivery.sh next        -> one action, its owner, its command (derived, never remembered)
Step 2  delegate the action, then: scripts/status.sh --change <id> --quiet; scripts/delivery.sh refresh
Step 3  repeat; the Stop hook guard-delivery-loop.sh refuses to end the turn while work remains

A failing review or test runs scripts/delivery.sh reopen. The verdict is kept in history/, one task is added per finding, and the next derived action is implement. The loop stops only for complete, for escalate (goal BLOCKED), for no progress, or when a human runs delivery.sh stop.

Enforcement

Hooks make standards executable.

EventGuard or validatorBlocks or reports
PreToolUse on writesguard-planning-handoff.shProduct code before an implementation plan.
PreToolUse on PRD/SPECS writesguard-context-preflight.shProduct docs without valid codebase context.
PreToolUse on story statusguard-story-done.shStatus: DONE before archive.
PostToolUse on product docsvalidate-product-artifacts.shMalformed PRD, SPECS, or Gherkin criteria.
Stopguard-delivery-loop.shEnding while an active delivery goal still has work.
Guards block with exit code 2; validators report malformed artifacts and keep failures visible.

Adaptation

Post-install makes the harness local.

1. Back up first

Copy current `.claude`, README, CLAUDE, and supported docs into docs/pre-install-backup/.

2. Read context

Use existing PRD.md, CODEBASE.md, and SPECS.md when present.

3. Write rules

Refresh `.claude/rules` for standards and validation in this codebase.

4. Refresh docs

Create or update root and nested CLAUDE.md plus README guidance.

5. Validate

Run frontmatter, product artifact, hook, and fast project checks.
