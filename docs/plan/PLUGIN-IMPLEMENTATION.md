There is no plugin `settings.json`, default agent, MCP server, implicit install-time script or copied consumer executable tree. The plugin discovers conventional sibling components through its manifest/loader. `rules/` is reference material, loaded explicitly by skills and the agents' scoped contract preload. Consumer `.claude/rules/` exists only when explicit adaptation creates project-specific guidance.

The 24 skill names are `contract`, `doctor`, `bootstrap`, `adapt-project`, `upgrade-project`, `migrate-legacy`, `harness-reset`, `post-install`, `analyze-codebase`, `generate-prd`, `ingest-spec`, `generate-html-page`, `deliver`, `product-iteration`, `plan-feature`, `review-feature`, `test-feature`, and seven `opsx-` operations: `explore`, `propose`, `update`, `apply`, `verify`, `sync`, `archive`. `post-install` delegates to the one adaptation engine. Lifecycle mutation skills require manual invocation. `contract` is internal. Legacy nested `opsx:*` command aliases were deliberately omitted; the names are a documented breaking change.

Scoped agents are `ohmyorch:codebase-analyst`, `product-specifier`, `spec-ingestor`, `planner`, `implementer`, `reviewer`, `tester`, `product-manager`. The first four retain read-only tool budgets and return authored handoffs for the main coordinator to persist. Implementer owns product code/tests and selected tasks. Reviewer/tester persist their own selected verdict, then return its path and summary; the coordinator reads and validates it. Product Manager delivery stays in the main session. No agent team or replacement workflow engine was introduced.

## Ownership, paths and operational behavior

| Asset | Owner and update policy |
|---|---|
| Installed skills, agents, hooks, scripts, templates and references | Plugin code; read-only during consumer operations. Resolve from the executing file's physical installation root. |
| PRD/SPECS/CODEBASE, OpenSpec changes/specs/history and delivery goal | Durable project intent/evidence. Adopt existing content without replacing it. Plugin update/uninstall preserves it. CODEBASE must come from analysis. |
| `project.json` | Explicit project opt-in and per-document mapping. Root/docs/mixed layouts supported; ambiguous duplicate documents require explicit mappings. Changing an existing mapping is a reviewed config edit followed by doctor. |
| `managed-files.json` and `managed-bases/` | Nonsecret project ownership/provenance. Commit with the project if shared. Bases contain only owned scaffolds/blocks, never surrounding user content or filled product documents. |
| Runtime leases/counters, local approval, affected-file backups | Private project-local generated state, Git-ignored. Not a plugin payload or public page artifact. |
| Provider settings, permissions, local credentials, unrelated hooks | User/project-owned. Never distributed, inferred from another machine, granted by bootstrap or backed up wholesale. |
| Root tests/tools, npm dependencies, release checks and public pages | Publisher-only assets outside the plugin; excluded by allowlisted packaging. |
| Historical reset trees/downloads and obsolete `.vscode/` | Removed from this publisher checkout by the user-authorized cleanup; never plugin runtime inputs. |

`bin/ohmyorch --project-root /absolute/project <operation>` is the public entry point. Skills use supported concrete `${CLAUDE_PLUGIN_ROOT}`, `${CLAUDE_PROJECT_DIR}` and `${CLAUDE_SESSION_ID}` substitutions; these do not imply ordinary Bash environment variables. Mutating delivery/state calls pass the actual session explicitly. Paths are canonicalized and checked for containment, traversal, control characters, symlink components and existing entry spelling. macOS `/var` and `/tmp` aliases resolve to their physical roots. Caller cwd and the checkout directory's name do not choose the project.

The runtime requires Bash >=3.2, jq >=1.6, Git, shasum and standard Unix utilities. Python/Node are maintainer-only requirements; OpenSpec is an explicitly installed external dependency with its own Node requirements. Supported delivery start and explicit OpenSpec initialization require **OpenSpec 1.13.2**. OpenSpec prompts reject registered stores/pointers, custom schemas and a context root different from the chosen local project. Doctor's lightweight schema check does not replace the OpenSpec CLI's real parsing/validation.

All internal calls use bundled code-root paths and project mappings. Missing activated validators block protected operations rather than downgrading gates. Action reports render shell-escaped installed paths, project roots and supplied session IDs. Their `command` field remains human guidance, sometimes containing slash commands or multiple separately described actions; never `eval` it or execute a stale stored goal command. Archive action guidance requires completion recording and archival in **separate Bash calls**.

## Bootstrap, adaptation, transactions and recovery

Bootstrap is explicit; plugin add/install/update and SessionStart do not initialize a project. Dry-run stages outside the project and creates no project file, backup or persistent lock. Apply creates only missing neutral documents/config/scaffolds; existing intent, README, CLAUDE, OpenSpec configuration and host scripts survive. `--mode merge` adds a bounded CLAUDE block. Existing configuration takes precedence over bootstrap's layout flags; remapping is explicit. `--with-openspec` invokes pinned OpenSpec initialization in a scratch directory with tools/cloud integration disabled, then stages only neutral reviewed local files.

Adaptation creates four owned project rules, evidence paths/hashes, explicit unknowns, and bounded README/CLAUDE blocks. It does not invent stack facts or runnable commands. Nested guidance requires `--nested` plus CODEBASE evidence for each actual top-level directory. Edited managed blocks, malformed markers, missing bases and unrelated files cause conflicts or preservation; there is no whole-file force overwrite.

Every mutation computes a plan with before/after hashes, obtains an atomic operation lock, creates private verified backups for **affected existing files only**, then uses per-file atomic replacement. The ownership ledger is separate from the durable recovery journal. Configuration activation is ordered last. Failure injection tests demonstrate recovery of already-applied writes. This is a journaled transaction, not a filesystem-wide atomic commit: abrupt termination can leave an operation lock and partial journal that require explicit recovery.

Managed reset touches only unchanged owned guidance. Workflow reset separately enumerates mapped PRD/SPECS and actual OpenSpec workflow files, preserving CODEBASE, host scripts, unknown docs and human nested guidance. Workflow reset and legacy migration apply require the exact reviewed plan ID. Legacy classification compares the 191 audited file fingerprints and exact event/matcher/command hook registrations; edited components are refused until separately included in a reviewed plan. Unknown customizations remain. Upgrade currently supports schema 1 and old counter relocation without altering the goal; unsupported future schemas require a real migration.

Rollback previews are read-only. Apply verifies backup contents and current after-hashes, restores only affected paths, and refuses to overwrite later edits. Empty directories/private records may remain. A killed operation requires inspecting its journal, confirming the process ended, removing only the empty operation lock, and running hash-guarded recovery. Never wipe runtime or backups wholesale.

## Hooks and preserved semantics

Root exec-form hooks route `PreToolUse` Write/Edit/MultiEdit, `PreToolUse` Bash, `PostToolUse` file writes, `Stop`, and `SessionStart` startup/resume/clear/compact. They receive structured JSON; top-level scoped `agent_type`/`agent_id` govern role dispatch. Prompt text cannot spoof a role. Ignored agent-frontmatter hooks are removed. Hook stdout is protocol JSON only; diagnostics/validator output use stderr. SessionStart supplies compact context without mutation.

Uninitialized projects are no-ops even without jq. An existing activation config requires jq to interpret it; explicitly disabled valid configurations return no action. Invalid activated config blocks protected pre-events while retaining a narrow `project.json` repair route. PostToolUse validation cannot undo a completed write. Exact selected-change role checks replace the old blanket subagent exception. Prospective SPECS validation reconstructs literal Write/Edit and sequential MultiEdit changes; unsupported prospective forms block rather than guessing.

An atomic owner lease records schema, session, project, acquisition/update time and goal target. A separate operation lock serializes state writes. Nonowner Stop events do nothing; takeover is explicit and no expiry is invented. Owner Stop derives the current action from artifacts. Three unchanged blocked stops precede the fourth unchanged stop, which writes BLOCKED and permits stopping. Config defaults to 3; the existing explicit `DELIVERY_MAX_STALLS` environment override remains. Claude's separate default eight-continuation cap resets on tool calls and is configurable; OhMyOrch does not depend on that platform counter. [Official hook behavior](https://code.claude.com/docs/en/hooks).

The seven gates, four distinct completion conditions, readiness/dependencies, action/goal vocabularies, parent-story acceptance for task focus, authored status notes and remediation history are retained. Blocking review findings and FAIL test results require fresh implementation/review/testing after reopen.

Observed baseline exceptions are preserved and independently tested: partial coverage is a warning; mixed PASS/UNVERIFIED can remain eligible when other checks pass; all-UNVERIFIED/no-positive-evidence fails; verification text can confuse the substring VERIFIED inside UNVERIFIED. The internal unavailable-CLI fallback remains for legacy evidence, while supported delivery start requires OpenSpec. The old DONE predicate can allow a currently eligible active change before archival; **archive-before-DONE is additionally a coordinator contract, not a newly proven universal mechanical archive check**. Strengthening any of these needs a separately versioned behavior decision.

These hooks are workflow guardrails. Arbitrary Bash/MCP writes and renamed archive executables can bypass file-tool checks. Detected archive commands must be standalone literal `openspec archive <id>` plus supported `-y`, `--yes`, `--skip-specs` flags; chained/dynamic forms are refused. Main-session product-code ownership also relies on the coordinator contract, while verdict and selected PM-state boundaries have explicit checks. No claim of process confinement is made.

A colocated `--plugin-dir` checkout remains editable maintainer source; it is not an immutable installation or confinement test. Consumer validation uses code outside the host or a real cache installation. Cache paths outside the selected project are rejected by the file-tool containment checks.

Host fast validation is disabled by default. Enabling it requires explicit config plus review and `run-project-validation --approve-current`; the approval must already be Git-ignored and binds the script's SHA-256. Changed/unapproved scripts are skipped. Local provider settings are neither sourced nor copied. Public Pages stages only `index.html`, `docs/OhMyOrch.html`, `docs/assets/` and `docs/images/`, excluding the repository's project/config/recovery trees.
