There is no plugin `settings.json`, default agent, MCP server, implicit install-time script or copied consumer executable tree. The plugin discovers conventional sibling components through its manifest/loader. `rules/` is reference material, loaded explicitly by skills and the agents' scoped contract preload. Consumer `.claude/rules/` exists only when explicit adaptation creates project-specific guidance.

The 20 skill names are `contract`, `doctor`, `bootstrap`, `adapt-project`, `upgrade-project`, `migrate-legacy`, `harness-reset`, `post-install`, `analyze-codebase`, `generate-prd`, `ingest-spec`, `generate-html-page`, `deliver`, and seven `opsx-` operations: `explore`, `propose`, `update`, `apply`, `verify`, `sync`, `archive`. `post-install` delegates to the one adaptation engine. Lifecycle mutation skills require manual invocation. `contract` is internal. The seven `opsx-` skills match the prompts OpenSpec 1.13.2 generates, apart from the plugin namespace and one boundary paragraph. Legacy nested `opsx:*` command aliases were deliberately omitted; the names are a documented breaking change.

Scoped agents are `ohmyorch:codebase-analyst`, `product-specifier` and `spec-ingestor`. All three keep read-only tool budgets and return authored content for the calling skill to persist. Delivery stays in the main session, which proposes, applies, verifies and archives each change itself. No agent team or replacement workflow engine was introduced.

## Ownership, paths and operational behavior

| Asset | Owner and update policy |
|---|---|
| Installed skills, agents, hooks, scripts, templates and references | Plugin code; read-only during consumer operations. Resolve from the executing file's physical installation root. |
| PRD/SPECS/CODEBASE, OpenSpec changes/specs/archive and delivery goal | Durable project intent/evidence. Adopt existing content without replacing it. Plugin update/uninstall preserves it. CODEBASE must come from analysis. |
| `project.json` | Explicit project opt-in and per-document mapping. Root/docs/mixed layouts supported; ambiguous duplicate documents require explicit mappings. Changing an existing mapping is a reviewed config edit followed by doctor. |
| `managed-files.json` and `managed-bases/` | Nonsecret project ownership/provenance. Commit with the project if shared. Bases contain only owned scaffolds/blocks, never surrounding user content or filled product documents. |
| Runtime leases/counters, local approval, affected-file backups | Private project-local generated state, Git-ignored. Not a plugin payload or public page artifact. |
| Provider settings, permissions, local credentials, unrelated hooks | User/project-owned. Never distributed, inferred from another machine, granted by bootstrap or backed up wholesale. |
| Root tests/tools, npm dependencies, release checks and public pages | Publisher-only assets outside the plugin; excluded by allowlisted packaging. |
| Historical reset trees/downloads and obsolete `.vscode/` | Removed from this publisher checkout by the user-authorized cleanup; never plugin runtime inputs. |

`bin/ohmyorch --project-root /absolute/project <operation>` is the public entry point. Skills use supported concrete `${CLAUDE_PLUGIN_ROOT}`, `${CLAUDE_PROJECT_DIR}` and `${CLAUDE_SESSION_ID}` substitutions; these do not imply ordinary Bash environment variables. Mutating delivery/state calls pass the actual session explicitly. Paths are canonicalized and checked for containment, traversal, control characters, symlink components and existing entry spelling. macOS `/var` and `/tmp` aliases resolve to their physical roots. Caller cwd and the checkout directory's name do not choose the project.

The runtime requires Bash >=3.2, jq >=1.6, Git, shasum and standard Unix utilities. Python/Node are maintainer-only requirements; OpenSpec is an explicitly installed external dependency with its own Node requirements. Supported delivery start and explicit OpenSpec initialization require **OpenSpec 1.13.2**. The OpenSpec prompts declare registered stores/pointers, global default stores and custom schemas out of scope; only the local `spec-driven` schema under `openspec/` is supported. Doctor's lightweight schema check does not replace the OpenSpec CLI's real parsing/validation.

All internal calls use bundled code-root paths and project mappings. Missing activated validators block protected operations rather than silently skipping a check. An action report's `command` field is human guidance, sometimes a slash command or more than one separately described action; never `eval` it or execute a stale stored goal command. No derived command invokes the `ohmyorch` CLI. The `verify` action's guidance requires the archive as a **separate, standalone Bash call**.

## Bootstrap, adaptation, transactions and recovery

Bootstrap is explicit; plugin add/install/update and SessionStart do not initialize a project. Dry-run stages outside the project and creates no project file, backup or persistent lock. Apply creates only missing neutral documents/config/scaffolds; existing intent, README, CLAUDE, OpenSpec configuration and host scripts survive. `--mode merge` adds a bounded CLAUDE block. Existing configuration takes precedence over bootstrap's layout flags; remapping is explicit. `--with-openspec` invokes pinned OpenSpec initialization in a scratch directory with tools/cloud integration disabled, then stages only neutral reviewed local files.

Adaptation creates four owned project rules, evidence paths/hashes, explicit unknowns, and bounded README/CLAUDE blocks. It does not invent stack facts or runnable commands. Nested guidance requires `--nested` plus CODEBASE evidence for each actual top-level directory. Edited managed blocks, malformed markers, missing bases and unrelated files cause conflicts or preservation; there is no whole-file force overwrite.

Every mutation computes a plan with before/after hashes, obtains an atomic operation lock, creates private verified backups for **affected existing files only**, then uses per-file atomic replacement. The ownership ledger is separate from the durable recovery journal. Configuration activation is ordered last. Failure injection tests demonstrate recovery of already-applied writes. This is a journaled transaction, not a filesystem-wide atomic commit: abrupt termination can leave an operation lock and partial journal that require explicit recovery.

Managed reset touches only unchanged owned guidance. Workflow reset separately enumerates mapped PRD/SPECS and actual OpenSpec workflow files, preserving CODEBASE, host scripts, unknown docs and human nested guidance. Workflow reset and legacy migration apply require the exact reviewed plan ID. Legacy classification compares the 191 audited file fingerprints and exact event/matcher/command hook registrations; edited components are refused until separately included in a reviewed plan. Unknown customizations remain. Upgrade currently supports schema 1 and old counter relocation without altering the goal; unsupported future schemas require a real migration.

Rollback previews are read-only. Apply verifies backup contents and current after-hashes, restores only affected paths, and refuses to overwrite later edits. Empty directories/private records may remain. A killed operation requires inspecting its journal, confirming the process ended, removing only the empty operation lock, and running hash-guarded recovery. Never wipe runtime or backups wholesale.

## Hooks and delivery semantics

Root exec-form hooks route `PreToolUse` Write/Edit/MultiEdit, `PreToolUse` Bash, `PostToolUse` file writes, `Stop`, and `SessionStart` startup/resume/clear/compact. They receive structured JSON; top-level scoped `agent_type`/`agent_id` govern role dispatch. Prompt text cannot spoof a role. Ignored agent-frontmatter hooks are removed. Hook stdout is protocol JSON only; diagnostics/validator output use stderr. SessionStart supplies compact context without mutation.

Uninitialized projects are no-ops even without jq. An existing activation config requires jq to interpret it; explicitly disabled valid configurations return no action. Invalid activated config blocks protected pre-events while retaining a narrow `project.json` repair route. PostToolUse validation cannot undo a completed write. The role check is inline in the dispatcher: a file-tool write from any `ohmyorch:*` agent is refused, and any other subagent is refused for the mapped SPECS and `openspec/delivery/*`. A write to an ordinary file spawns no guard script. Writes to the mapped PRD and SPECS run the CODEBASE-staleness preflight, except a SPECS write that is only delivery bookkeeping: `Status:` lines, `Change:` lines, story and task rows of the Work Item Status table and pure task ticks (blank lines are ignored). The preflight reads the prospective document: a `CODEBASE Context: skipped` line, or `CODEBASE Context: consumed (<recorded revision>, staleness accepted)`, lets the write proceed, and commits that touch only the three mapped documents do not make the analysis stale. Prospective SPECS validation reconstructs literal Write/Edit and sequential MultiEdit changes; unsupported prospective forms block rather than guessing. The reconstructed document reaches the DONE guard as a file, because Linux refuses a single argument of 128 KiB or more.

An atomic owner lease records schema, session, project, acquisition/update time and goal target. A separate operation lock serializes state writes. Nonowner Stop events do nothing; takeover is explicit and no expiry is invented. Owner Stop derives the current action from artifacts once when it keeps the session working; a stop that records BLOCKED derives again through `delivery block`. Three unchanged blocked stops precede the fourth unchanged stop, which writes BLOCKED and permits stopping. Config defaults to 3; the existing explicit `DELIVERY_MAX_STALLS` environment override remains. Claude's separate default eight-continuation cap resets on tool calls and is configurable; OhMyOrch does not depend on that platform counter. [Official hook behavior](https://code.claude.com/docs/en/hooks).

Delivery derives one of six actions (`propose`, `apply`, `verify`, `mark-done`, `escalate`, `complete`) from SPECS and the change directory on every call; `goal.md` is a record. Readiness and dependency checks, the goal vocabulary (ACTIVE, BLOCKED, STOPPED, COMPLETE), parent-story acceptance for task focus and authored goal notes are retained. A change's only artifacts are OpenSpec's own (`proposal.md`, delta `specs/`, optional `design.md`, `tasks.md`). `tasks.md` is the only tracker, and a CRITICAL verify finding becomes a new unticked task.

Two guards are mechanical. The archive guard refuses a detected `openspec archive <id>` while that change's `tasks.md` has an unfinished task, counted with the patterns of OpenSpec 1.13.2's own counter; a change with no task checklist is allowed, and OpenSpec validates and merges the delta specs itself. The DONE guard refuses a SPECS write that newly sets a story to `Status: DONE` while the story's change is still an active directory under `openspec/changes/`. It judges the `Change:` id in the prospective SPECS and the one on disk, and every active `us-<n>-<m>-*` directory. The derivation reads the same directories, so `mark-done` is never derived while one of them is active. Verify is advisory and writes no file, so neither guard asserts that an implementation is correct. The partial/UNVERIFIED acceptance and verification-text exceptions recorded for 0.0.1 no longer apply: the evaluators that carried them were removed in the separately versioned 0.1.0 decision, not strengthened.

These hooks are workflow guardrails. Arbitrary Bash/MCP writes and renamed archive executables can bypass file-tool checks. Detected archive commands must be standalone literal `openspec archive <id>`, with the id bare or in one pair of quotes, plus supported `-y`, `--yes`, `--skip-specs` flags; chained/dynamic forms, a global option before `archive` and multi-line commands are refused. The `opsx-archive` skill's own move of a change directory is not intercepted. Delivery state (the mapped SPECS and `openspec/delivery/*`) has explicit lease and role checks. No claim of process confinement is made.

A colocated `--plugin-dir` checkout remains editable maintainer source; it is not an immutable installation or confinement test. Consumer validation uses code outside the host or a real cache installation. The file-tool checks refuse a target inside the installed plugin and, for a cache installation, anywhere in Claude's plugin directory except its `data` directory; a target physically outside the project and that directory is not judged. A project that itself contains the plugin directory is not covered: its own files are judged as project files.

Host fast validation is disabled by default. Enabling it requires explicit config plus review and `run-project-validation --approve-current`; the approval must already be Git-ignored and binds the script's SHA-256. Changed/unapproved scripts are skipped, and the post-write hook does not spawn the adapter while fast validation is disabled. Local provider settings are neither sourced nor copied. Public Pages stages only `index.html`, `docs/OhMyOrch.html`, `docs/assets/` and `docs/images/`, excluding the repository's project/config/recovery trees.

The owner asked for a faster process that keeps only what is part of OpenSpec, and chose "Pure OpenSpec + verify" driven from the SPECS backlog. Each READY story is now one OpenSpec change that the main session takes through propose, apply, verify and archive; then the story is marked DONE. This replaces the layered contract that the sections dated 2026-10-06 and 2026-10-07 describe. Those sections are unchanged and keep the counts and vocabulary of their snapshot.

- **Removed.** Skills `plan-feature`, `review-feature`, `test-feature` and `product-iteration`; agents `planner`, `implementer`, `reviewer`, `tester` and `product-manager`; rule reference `testing.md`; the three templates under `templates/artifacts/`; and 11 scripts with their CLI operations: `workflow-status`, `status`, `completion-gate`, `validate-implementation-plan`, `validate-review`, `validate-test-report`, `validate-status`, `validate-verification`, `check-write-scope`, `check-scope` and `guard-planning-handoff`. `delivery reopen` and the `--change` option are gone.

- **Guards.** Archive is refused while `tasks.md` has an unticked task. DONE is refused while the story's change is still active, which is stricter than the earlier predicate for an unarchived change that only looked eligible. Neither guard spawns another script.

Fast validation is spawned only when enabled. The dispatcher initializes the runtime once instead of twice; each script it spawns still initializes on its own.

### Review fixes

An independent review ran on this working tree on the same day, before any commit. These fixes are part of 0.1.0.

- **Task counting.** The derivation and the archive guard count `tasks.md` with the patterns of OpenSpec 1.13.2's own counter, so `- [~]`, `- [-]`, `- []`, `* [ ]` and `1. [ ]` are unfinished tasks. Recheck the patterns on an OpenSpec bump.
- **DONE guard.** It judges the `Change:` id in the prospective SPECS and the one on disk, and every active `us-<n>-<m>-*` directory, so a `Change:` line reworded in an earlier write does not detach a story from its active change. It finds newly DONE stories in one awk pass.
- **Derivation.** An active change wins over an archive of the same id. `skip_specs` accepts `true`, `True` and `TRUE` with an optional trailing comment. `specs/` needs at least one `.md` file. A SPECS with CRLF line endings is parsed. A title that yields an empty slug derives `us-<n>-<m>-story`. The goal record builds its story rows, and the derivation finds the first story that is not DONE, with one awk pass each. The change directories are listed at most once per run, so in the goal record and the derivation a story without a `Change:` line costs no process of its own. The lookup walks the listing line by line, because bash 3.2 takes quadratic time to cut a long string at a pattern; with 1,231 archived changes a Stop still answers in under a second. The derived id is computed byte-wise and is the same in every locale. Whether a change is archived is decided by comparing its id, as text, with one listing of the real directories under the archive: no pattern, no pathname expansion, no symbolic link.
- **SPECS bookkeeping.** The carve-out covers the story and task rows of the Work Item Status table. On a task line only the box and the whitespace before it may change: the two versions are compared with every box blanked, so a task line that is added, reworded, moved or deleted is a material edit. A failed comparison step keeps the preflight.
- **CODEBASE preflight.** The two decisions its messages offer now work when they are written into the PRD or SPECS being saved. Commits that touch only the three mapped documents do not make the analysis stale. `detect_codebase` was changed afterwards; see the owner decisions below.
- **Archive interception.** The id may be quoted. A global option before `archive`, a version-pinned `openspec@…` and a multi-line command are refused.
- **Fail closed.** In an enabled project a missing `delivery.sh` or `validate-product-artifacts.sh` is reported as a missing bundled validator in every hook mode. Every refusal by the dispatcher prints its reason on stderr.
- **Lifecycle.** `adapt-project` refreshes an `openspec/config.yaml` whose hash still equals its recorded scaffold. An edited or unrecorded one is left alone.
- **Prompts.** `deliver` records a missing human decision with `delivery block --reason` before it stops, names what is CRITICAL in this loop, resumes the recorded goal when it gets no argument, and acts on the action `delivery start` prints.
- **Documentation.** The changelog, handbook, guide and distribution guide give the upgrade steps from 0.0.1 and label the 2.1.285 and 2.1.292 results as 0.0.1 results.
- **Tests.** Each fix has at least one assertion that fails when the fix is reverted as a whole. Finer mutations of single clauses were also run in scratch copies; a few that need hand-made directory names still pass. A mutant run in scratch copies of the repository reported 70 of 70 mutants failing a suite. At integration 18 of those were run again and all 18 failed as expected. One plugin test was added at integration for the path `deliver` now depends on: the owner's `delivery block --reason` records BLOCKED, the next Stop is allowed without output, and `delivery start` with the same target resumes the goal as ACTIVE. It fails on two mutants of `delivery block`. A second verification pass then found four gaps, which are closed and pinned: the DONE guard after a `Change:` line reworded in an earlier write, the position of a moved task line, the cost per story without a `Change:` line in the goal record, and the validator's advice for a recorded skip decision. A third pass checked those four fixes and led to the literal archived test, the locale-independent id and the fail-closed comparison step. A fourth found that the directory lookup written in the second took quadratic time on a long archive, and that the archived test depended on shell options and followed symbolic links; both are replaced and pinned.
- **Maintainer instructions.** `CLAUDE.md` now says that the catalog is served from the default branch, so pushing `main` delivers the manifest version to users who update, whether or not a tag exists, and that the archive guard counts an unfinished task as OpenSpec counts them.

### Owner decisions — 2026-11-13

The owner agreed to four changes the review had left open. They follow the first 0.1.0 commit and are part of 0.1.0.

- **Targets outside the project.** A file-tool target that is physically outside the project and Claude's plugin directory is no longer refused, so Claude's own plan, memory and scratch files can be written in an activated project. Containment is judged on the physical path of the nearest existing directory and compared by identity. No other route to a file inside the project skips a guard: a symbolic link, a traversal, another letter case of the project root and an inode path (`/.vol/…` on macOS) are refused, and a doubled slash is judged as the path it names. A target that is itself a symbolic link is refused wherever it points, and so is any path that contains `..` or is longer than 4,096 characters. For a cache installation the plugin directory (other versions, marketplace clones, the install records) stays out of reach, apart from the per-plugin `data` directories; it is recognised by its `plugins/cache/<marketplace>/<plugin>/<version>` shape, so a relocated cache protects the plugin root only, as a `--plugin-dir` checkout does. An `ohmyorch:*` agent is refused everywhere. A hard link made outside the project to a file inside it is not detected. Whether Claude Code's plan-mode and memory writes reach the hook was not observed in a live session.
- **CODEBASE detection.** A repository without a package manifest is recognised as a codebase whatever its listing of source files looks like. Before, a listing longer than about 16 KiB (roughly a thousand files) had its writer cut off under `pipefail`, and a listing that `find` could not finish because of an unreadable directory failed the same way; both passed as an empty project. Not changed: the manifest and extension lists. A project recognised only by `build.gradle.kts`, `build.sbt` or `pubspec.yaml`, or whose sources all sit deeper than three levels, still reads as greenfield.
- **DONE after a misdirected `Change:` line.** When a story's `Change:` line names an archived change while a directory named for the story is still active, the derivation escalates instead of deriving `mark-done`, and the DONE guard judges those directories without exception. A directory name that holds a newline is not a change for either of them. The guard no longer needs its own archived test.
- **Validated versions.** The manifest's `formatValidatedClaudeCode` and `cacheLifecycleValidatedClaudeCode` name 2.1.314, the version on which those checks ran for 0.1.0.

## Remaining public-artifact/support gates and explicit limits

The authoritative checklist is [plugin-release-readiness.json](plugin-release-readiness.json). `rollbackRehearsed` is true. License approval, live agent identity/denials, live full delivery and latest-stable full runtime validation remain false. Manifest `testedClaudeCode` is intentionally empty; separate metadata names report format/cache evidence without implying live support.

Before public packaged artifacts or support claims, an authenticated disposable session must prove `/agents` and skill discovery, scoped contract preload, actual plugin root/project/session substitution, the write denials for the three read-only authoring agents and for other subagents on delivery state (including generic and `--agent` identities), one firing of each hook, one complete propose/apply/verify/archive/DONE story, a CRITICAL verify finding returning the change to apply, resume/compaction and owner/nonowner/takeover behavior. Record only necessary identity/event/result metadata; do not publish credentials or full transcripts. Run the matrix on the then-current official stable CLI and CI platforms; increment version/evidence together if code changes. These checks were intentionally deferred, not silently skipped as passing.

Native Windows, registered/global OpenSpec stores, custom schemas, unsupported prospective file-tool payloads and old CLI versions lacking exec-form args are unsupported. Broader monorepo layouts and arbitrary external tools require explicit adapters, not permissive fallback. No shell alias/MCP/process-confinement guarantee exists. Immutable prior refs and same-scope reinstall are the code rollback strategy; there is no invented `plugin update --version` option.

The owner must select a real distribution license, add the actual plugin LICENSE/SPDX field, review upstream notices and approve support commitments before public packaged artifacts or support claims. The release workflow only prepares gated artifacts. The repository marketplace and local `--plugin-dir` flow expose the published source version without changing those gates. Official marketplace listing is optional and separate from this self-hosted catalog.
